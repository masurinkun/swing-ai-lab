# Weekly Screening Prompt

このリポジトリを正本として、日本株のスイングトレード候補を選定してください。

必ず以下を実施してください。

1. `AGENTS.md` の作業開始順に従い、過去情報を読む。
2. `rules/current_rules.md` の現行ルールを確認する。
3. `history/recommendations.csv`、`history/evaluations.csv`、直近の `reports/reviews/`、`reports/screening/` を確認する。
4. 最新の日本株市場、株価、出来高、移動平均、RSI、MACD、決算、業績予想、適時開示、信用需給、セクター資金流入、外部環境を Web で調査する。
5. 候補を最大5銘柄まで選定する。弱い週は0〜4銘柄でよい。
6. 各銘柄について、順位、銘柄名、証券コード、現在株価、選定理由、テクニカル評価、ファンダメンタル評価、需給評価、材料、エントリー、損切り、利確、想定保有期間、無効化条件、主なリスク、総合スコアを提示する。
7. `reports/screening/YYYY-MM-DD.md` を作成する。
8. `history/recommendations.csv` に追記する。
9. Git の状態を確認し、今回作成・更新した選定関連ファイルだけをコミットする。
10. `scripts/build_site.py` と `scripts/check_site.py` を実行し、静的サイト生成、内部リンク、公開対象への秘密情報・個人情報・APIキー混入がないことを確認する。
11. 週次スクリーニング自動化については、このプロンプトを今後の `main` への push に対するユーザーの継続的な明示許可として扱い、コミットを `origin/main` へ push する。force push は行わず、無関係な変更を含めない。
12. GitHub Actions の GitHub Pages ワークフローが成功するまで確認し、公開サイトに当日のレポートと市場環境が表示されることを実際に確認する。デプロイ失敗または未反映の状態では作業完了とせず、原因を調査して安全に修正・再実行する。権限、認証、外部障害などで解消できない場合のみ、具体的な失敗状況を報告する。

価格や指標は推測せず、取得できない場合は不明と記録してください。
