# Weekly Screening Prompt

このリポジトリを正本として、日本株の1〜3週間のスイングトレード候補を選定する。価格や指標を推測せず、取得できない項目は不明と記録する。推薦候補は分析補助であり、注文執行や自動売買は行わない。

## 1. 過去評価と今回の改善

1. `AGENTS.md` の作業開始順に従い、過去情報を読む。
2. `rules/current_rules.md`、`rules/rule_candidates.md`、`history/recommendations.csv`、`history/evaluations.csv`、直近の `reports/reviews/` と `reports/screening/` を確認する。
3. 評価期限が到来した推薦に未評価分があれば、原則として `prompts/weekly_review.md` に従う評価を先に行う。
4. 分析冒頭に、直近の評価済み失敗理由を最大3件で要約し、今回はどう改善するかを書く。評価済みの失敗がない、またはサンプル不足の場合は、その事実を書き、失敗理由を推測しない。
5. 検証中の候補ルールは比較記録に使えるが、採用済みルールとして強制しない。

## 2. 市場環境

日経平均、TOPIX、グロース250、USD/JPY、米国主要指数、SOX、VIX、長期金利、海外投資家動向、セクター動向を可能な範囲で確認する。各データに基準日時を付け、取得できない補助データは不明とする。

市場を `Risk On`、`Neutral`、`Risk Off` のいずれかに分類し、今週の中心戦略を `順張り`、`押し目買い`、`見送り中心` から選ぶ。市場環境は候補数、確認条件、データ信頼度へ反映するが、市場環境だけで個別銘柄を一括除外しない。

## 3. 一次スクリーニングとセクター分析

1. 東証プライムを優先し、原則30銘柄以上を一次確認する。スタンダードとグロースは、流動性、ボラティリティ、信用需給を確認できる場合に加える。
2. 一次確認では、流動性、トレンド、相対強度、決算日程、業績方向、直近材料を用いて絞り込む。
3. 確認銘柄数、確認範囲、絞り込み方法、資金流入・流出が示唆されるセクターをレポートに記載する。
4. 同一セクターは原則最大2銘柄とする。

## 4. 必須データと補助データ

推薦に必須なのは、基準日時付き最新株価、調整を確認できる日足OHLCV、株式分割・併合、決算予定日、直近業績、流動性、およびEntry・Stop・Target・リスクリワードを根拠ある数値で設定するための価格情報とする。

RSI、MACD、一目均衡表、空売り比率、貸借倍率、週次信用需給、海外投資家動向、定量的セクター資金流入、SOX、VIXなどは補助データとする。補助データの一部欠損は、それだけで候補から除外せず、スコアとデータ信頼度を下げる。

## 5. 銘柄分析

上位銘柄について以下を総合評価する。

- テクニカル: 5日、20日、25日、75日移動平均、傾き、トレンド、高値更新、安値切り上げ、押し目、もみ合い上放れ、支持線、抵抗線、ローソク足、出来高、25日線乖離、RSI、MACD、一目均衡表、リスクリワード
- ファンダメンタル: 売上高・営業利益成長、利益率、通期進捗率、ROE、自己資本比率、PER、PBR、増配、自社株買い、上方修正、大型受注、業務提携
- 需給: 出来高、売買代金、信用倍率、信用買残、空売り比率、貸借倍率、海外投資家動向、セクター動向
- イベント: 決算、適時開示、増配、上方修正、自社株買い、M&A、大型契約、地政学、金利、為替

`rules/current_rules.md` のハード除外と減点を分けて適用する。複数の減点が重なって除外する場合は、どの売買条件を設定できなくなったかを具体的に説明する。

## 6. 推薦候補とエントリー判定

候補は最大5銘柄とする。推薦候補と即時のエントリー可否を分け、各銘柄を `条件付き候補`、`エントリー条件成立`、`無効` のいずれかで判定する。

条件付き候補では、押し目反発、支持線維持、出来高を伴うブレイクなど、確認すべきトリガーを明示する。条件未成立を理由に推薦候補そのものから落とさない。ただし、Entry、Stop、Targetを根拠ある価格で設定できない銘柄は監視にとどめる。

0銘柄は、原則30銘柄以上を一次確認し、上位候補がすべてハード除外条件に抵触した場合に限る。0銘柄の場合は、確認銘柄数、上位5銘柄、各銘柄が抵触したハード除外条件を記載する。30銘柄を確認できない場合は「0銘柄」ではなく「データ不足で選定未完了」とする。

推薦候補が1銘柄以上ある場合のみ本命と次点を示す。0銘柄の場合は本命・次点をともに該当なしとする。

## 7. レポート出力

最初に以下を記載する。

- データ基準日時
- 評価済みの前回失敗理由と今回の改善
- 市場分類、中心戦略、セクター動向、注意点
- 一次確認銘柄数、確認範囲、絞り込み方法

候補ランキングでは、各銘柄について以下を記載する。

- 順位、銘柄名、証券コード、セクター、現在株価
- 総合スコア、データ信頼度（高・中・低）、判定、一言結論
- テクニカル、ファンダメンタル、需給、材料
- Entry、Stop、Target 1、Target 2、想定保有期間
- エントリートリガー、無効化条件、主なリスク

最後に、本命、次点、上位見送り銘柄、セクター集中リスクを記載する。

## 8. 自己レビュー

分析後に必ず以下を書く。

- 最も不確実な点
- 外れるとしたら何が原因か
- データ取得上の制約
- 来週改善したい点

改善案は仮説、根拠、必要サンプル数を示し、`rules/rule_candidates.md` に候補ルールとして記録する。1週間だけの結果で `rules/current_rules.md` を変更しない。

## 9. 記録・公開

1. `reports/screening/YYYY-MM-DD.md` を作成する。
2. 推薦候補を `history/recommendations.csv` に追記する。監視のみで売買条件を設定できない銘柄は追記しない。
3. 必要な市場環境を `history/market_environment.csv` に追記する。
4. Gitの状態を確認し、今回作成・更新した選定・評価関連ファイルだけをコミットする。
5. `scripts/build_site.py` と `scripts/check_site.py` を実行し、静的サイト生成、内部リンク、公開対象への秘密情報・個人情報・APIキー混入がないことを確認する。
6. 週次スクリーニング自動化については、このプロンプトを今後の `main` へのpushに対するユーザーの継続的な明示許可として扱い、コミットを `origin/main` へpushする。force pushは行わず、無関係な変更を含めない。
7. GitHub ActionsのGitHub Pagesワークフローが成功するまで確認し、公開サイトに当日のレポートと市場環境が表示されることを実際に確認する。デプロイ失敗または未反映の状態では作業完了とせず、安全に原因を調査する。権限、認証、外部障害などで解消できない場合のみ具体的な失敗状況を報告する。
